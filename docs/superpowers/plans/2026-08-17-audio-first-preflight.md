# Что закрыть до включения маршрута «монтаж от звука» — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Довести маршрут audio-first до состояния, в котором его можно включить на реальном ролике: убрать пути, где оплаченный прогон виснет или выдаёт брак со статусом «готов», и покрыть сквозным прогоном несущую часть, которая сейчас держится только на модульных тестах.

**Architecture:** Все шесть пунктов — внутри нового маршрута, старый путь ни один из них не затрагивает. Пять правок точечные (защита от дублей, fallback длительности, атомарная запись, разведение «маршрут выбран» и «трек есть», честный отказ при деградированном выравнивании). Шестая — доработка мок-провайдера, чтобы сквозной прогон проходил через нарезку кусков трека и lip-sync.

**Tech Stack:** Nuxt 4 / Nitro, Bun, TypeScript, Prisma + PostgreSQL 16, Vitest (`vitest.pure.config.ts` — DB-free, `vitest.config.ts` — с БД), FFmpeg через `fluent-ffmpeg`, Replicate.

**Spec:** `docs/superpowers/specs/2026-08-16-audio-first-editing-design.md`
**Предшествующий план:** `docs/superpowers/plans/2026-08-16-audio-first-timing.md` (выполнен, 30 коммитов, ветка `feat/audio-first-timing`)

## Global Constraints

- Пакетный менеджер **Bun**, не npm. Тесты: `bunx vitest run --config vitest.pure.config.ts <путь>`.
- БД меняется только миграциями, `prisma db push` запрещён.
- **Старый маршрут не ломается.** Ни одна правка этого плана не должна менять поведение роликов без флага. Это проверялось на каждой задаче предыдущего плана и остаётся главным инвариантом.
- Все долгие и платные операции идемпотентны и переживают рестарт: повтор не платит второй раз и не теряет результат.
- Ролик не может дойти до статуса «готов» в заведомо сломанном виде. Честный отказ дешевле брака — это принятое решение (§4.1, §10 спеки).
- Комментарии и сообщения об ошибках — по-русски.
- Не создавать файлы-монстры; чистую часть отделять от запуска процессов (образцы: `buildSegmentCutArgs`, `buildStillClipArgs`, `parseSilenceRangesFromStderr`).
- Ни одного платного вызова в тестах.

### Task 1: Дубли номера сцены роняют выравнивание, и отказ уходит мимо учёта денег

Воспроизведено ревьюером: `alignScriptToTranscript` со сценами, у которых совпадает `order`, падает с `TypeError: undefined is not an object (evaluating 'words[0].startSec')`. Причина в `align.ts:269`: `tokens.filter(token => token.sceneOrder === scene.order)` при дубле считает токены обеих сцен, курсор уезжает, второй сцене достаётся пустой срез.

Дубли `order` — известная реальность этого проекта: `lip-sync-runner.ts` специально пишет о них WARN, `indexPlanScenesByOrder` выбрасывает неоднозначные значения. Выравнивание — единственный новый потребитель, который на этом падает.

### Task 6: Сквозной прогон должен проходить через нарезку кусков и lip-sync

Сейчас сквозной тест обходит несущую часть маршрута. Непроверенной остаётся вся связка «границы выравнивания → кусок трека → lip-sync клип → длина клипа → склейка», притяжка к границе кадра, идемпотентность нарезки при повторе и маршрут-специфичный ключ отказа.

Причина известна: классификатор мока не знает эндпоинтов Replicate и пишет JSON-заглушку под именем `.mp4`, которую ffmpeg не склеит.

**Оценка исполнителя предыдущего плана (учесть при планировании времени):** это не часовая работа. Правка меняет то, что получает **каждый** потребитель мока — включая первую integrated спеку `text_to_image` (дефолт реестра для кадров) и HTTP-контур вариаций персонажа, — поэтому нужен прогон тяжёлой сьюты `tests/api`. ## Что этот план сознательно НЕ делает

- **Canary на реальных деньгах** — задача 14 предыдущего плана. Требует токена Replicate и бюджета владельца; после этого плана она становится осмысленной, но остаётся отдельным решением.
- **Второй вызов Anthropic без имени агента** в валидаторе промптов сцены: прод не задет, но каждый мок-прогон молча идёт по деградированной ветке пост-валидации. Отдельный тикет.
