# Монтаж от звука: единая озвучка, тайминги слов и план кадров

Дата: 16 августа 2026 года. Продолжает `docs/superpowers/specs/2026-08-14-avatar-pipeline.md` (аватарный маршрут) и меняет то, чего та спека не касалась: порядок производства ролика.

Повод — разбор чужой работающей системы того же класса (SaaS для Reels с AI-аватаром). Её схема проще нашей, но три решения в ней устроены честнее, и они переносимы. Ниже — что именно берём, что не берём и почему.

---

## 1. Что не так сегодня

### 1.1 Речь подгоняется под картинку

Реальный порядок шагов — `server/utils/video-pipeline-run-policy.ts`: `prompt → image → clip → lip_sync → voiceover → music → assembly`. Речь синтезируется **внутри** шага lip-sync, посценно, отдельным вызовом на каждую сцену.

Отсюда следствия, каждое из которых уже чинилось отдельным коммитом:

- фрагмент ведущего ищется по длительности с допуском ±1 с (`server/utils/presenter-source-selector.ts`), а если реплика в него не влезает — **ускоряется голос** до 1.2x (`planSpeechFitToModel`, `adjustAudioTempo` в `server/utils/lip-sync-runner.ts`);
- между тейками вставляется искусственный вдох, потому что отдельные файлы иначе стыкуются встык;
- интонация рвётся на каждой границе сцены: модель не знает, что было до и что будет после.

Это лечение симптомов одной причины. Голос — эталон времени в ролике, а у нас он подчинённая величина.

### 1.2 Тайминги слов не существуют

`server/utils/subtitles/word-timings.ts` распределяет длительность сегмента по словам поровну с минимумом 200 мс. В файле это написано прямым текстом: «Whisper word-level timings ещё не используются в pipeline». Транскрипция в проекте есть, но только для анализа **чужих** видео (`server/utils/video-content-analyzer.ts`, через fal).

Следствия: караоке-пресеты подсвечивают не то слово; границы сцен известны лишь по плану, а не по факту; проверить, что реплика уложилась в кадр, нечем, кроме ffprobe всего файла.

### 1.3 Картинка меняется раз в сцену

Сцена длится 5–10 секунд одним планом. Смягчено медленным движением внутри кадра (`server/utils/video-tools/shot-variation.ts`), но структурно ролик остаётся набором длинных статичных сцен. Практика короткого видео — смена картинки каждые 1.5–2 секунды, и она же работает на уникальность: платформы сравнивают последовательность перцептивных хэшей, снятых с шагом порядка секунды.

### 1.4 Монтаж не управляем снаружи

Правил монтажа как сущности нет. Нельзя сказать «чередуй двух ведущих каждые пять секунд», «под этого ведущего фон не подставляй», «первым кадром покажи запись экрана». Всё, что можно, — переписать промпт сценариста.

### 1.5 Библиотеки фонов нет

Перебивка — только сгенерированная картинка или скрин приложения. Показать в CTA сам лид-магнит, канал или форму нечем, хотя для воронки с кодовым словом это ровно тот кадр, который двигает конверсию.

## 2. Принятые решения (16 августа 2026)

| Вопрос | Решение |
|---|---|
| Озвучка | Единый трек на весь сценарий, сцены нарезаются из него по фактическим таймингам |
| Кто ставит границы кадров | Два уровня: смысловые сцены остаются за сценарным агентом, кадры внутри них нарезает монтажный проход |
| Визуальный слой | Библиотека загружаемых фонов + наложение ведущего (PiP) + генерация фонов и картинкой, и видео |
| Генеративное видео на фон | Разворот решения от 14.08 («клип на перебивку не покупаем»): разрешено как **опция** профиля, с потолком стоимости и только для кадров от 5 секунд — короче модели не продают (§7) |
| Где живут правила монтажа | Монтажный профиль (бренд/шаблон) + переопределение на ролике. Автономный режим берёт из профиля |
| Правка озвучки | Единый трек не отменяет точечной правки: одна фраза пересинтезируется и вклеивается по паузам (§4.5), маркеры пауз дают монтажу управляемый ритм (§4.6) |
| Исходные записи ведущего | Хранятся нормализованными, с дедупом, автоочисткой и повторной нарезкой (§6.1) — это отдельная задача, а не побочный эффект |
| Ручной контроль | Опциональный полный пошаговый режим: пайплайн ждёт решения оператора после каждого шага |
| Способ внедрения | Основной пайплайн переводится на audio-first; переключатель `EDIT_PIPELINE` живёт до canary-сравнения со старым маршрутом, затем удаляется вместе со старой веткой |

## 3. Новый порядок шагов

```
prompt_generation      сценарий и смысловые сцены (без изменений)
voiceover_generation   ОДИН вызов TTS на весь текст ролика
transcription          новый шаг: слова с таймингами
edit_plan              новый шаг: кадры, фоны, ведущие
image_generation       фоны по плану (картинка / видео / библиотека)
clip_generation
lip_sync_generation    нарезка исходника под кадр + синхронизация
music_generation
assembly               сборка кадров, PiP, непрерывный звук, субтитры
```

`STEP_ORDER` в `server/utils/video-pipeline-db.ts` — персистентный `stepIndex`, переставлять его нельзя: по нему записана история роликов. Новые ключи дописываются в конец. Реальный порядок задаёт `STEP_EXECUTION_ORDER`; расхождение этих двух списков уже существует ради lip-sync и документировано там же.

Смысл шага `voiceover_generation` меняется: был микс посценных реплик под готовые клипы, становится синтез единого трека. Lip-sync перестаёт синтезировать речь сам и становится потребителем кусков этого трека.

Лимит модели проверен: `minimax/speech-02-turbo` принимает 5000 символов за вызов (`constraints.maxCharacters` в `server/utils/media-provider/model-specs.ts`), ролик 70–90 секунд — около 1200. Запас четырёхкратный.

### 3.1 Что тянет за собой перестановка

**Каскад перезапуска.** Новые ключи заводятся в `STEP_EXECUTION_ORDER` (`server/utils/video-pipeline-run-policy.ts`) и в `assetTypesForSteps` (`server/utils/video-pipeline-reset.ts`), иначе `rerun-step` оставит протухшие транскрипт и план монтажа лежать рядом со свежей озвучкой. Транскрипт хранится как ассет ролика, план — в таблице `VideoShot` (§5.2); перезапуск озвучки сбрасывает оба, перезапуск плана — только кадры.

**Политика `voiceoverReconciliation` отключается на новом маршруте.** Значения `compress_audio` и `extend_scene` (`server/utils/render.ts`, `server/utils/pipeline-executors.ts`) существуют, чтобы мирить длину реплики с длиной клипа: первое сжимает звук, второе растягивает сцену и подменяет клипы файлами `*_ext.mp4`. При audio-first мирить нечего — кадр нарезан по речи. Оставленная включённой, эта ветка подменит клипы под несуществующую проблему и подерётся с новым таймлайном.

**Ролики, недоделанные на момент выкатки,** дорабатываются старым маршрутом: у них записаны `stepIndex` и снапшоты прежнего порядка. Признак маршрута фиксируется на ролике при старте прогона, а не читается из глобального флага, — иначе смена `EDIT_PIPELINE` посреди производства даст ролик, собранный наполовину по одним правилам, наполовину по другим.

## 4. Транскрипция и выравнивание

### 4.1 Способность `transcription`

Новая способность медиареестра (восьмая — в `server/utils/media-provider/types.ts` их сейчас семь). Вход нормализованный:

```ts
TranscriptionInput {
  audioUrl: string
  language?: string     // подсказка; ru по умолчанию для нашего контура
}
```

Выход — слова с границами: `{ text, startSec, endSec }[]` плюс полный текст. Структура совпадает с `WhisperWordChunk` / `parseWhisperWords`, которые уже написаны в `server/utils/subtitles/word-timings.ts` как точка расширения.

Провайдер — Replicate (обязателен по `AGENTS.md`). Конкретная модель и её тариф снимаются со страницы модели перед включением: API Replicate цен не отдаёт вовсе, это проверено при работе над аватарными моделями. До подтверждения тарифа спека остаётся `integrated: false`.

### 4.2 Выравнивание — отдельный чистый модуль

Whisper слышит «эм эр эр», в сценарии написано «MRR». Поэтому слова транскрипции сопоставляются со словами сценария по сценам: нормализация (регистр, пунктуация, числительные, латиница) и сопоставление по редакционному расстоянию на уровне слов. Результат — фактические границы каждой сцены и каждого слова.

Модуль без БД и без сети, покрывается тестами полностью.

**Субтитры при этом берут текст из сценария, а тайминги из выравнивания.** LLM-коррекция транскрипции, которую пришлось делать автору разобранной системы, нам не нужна: у нас есть исходный текст, и подставлять распознанное незачем.

### 4.3 Почему аудио не режется

В разобранной системе аудио режут и склеивают, потому что каждый кусок отдельно уходит в lip-sync. Отсюда поиск самого тихого места между словами и притяжка к границе кадра — иначе на стыках щелчки.

У нас финальный звук остаётся **одним непрерывным файлом**: он кладётся под таймлайн целиком. Отдельный аудио-lane в сборке уже существует (`voiceoverPath` в `server/utils/render.ts`). Резать аудио нужно только на входе lip-sync, и эти куски в финал не попадают — из них берётся картинка.

Следствие: щелчков на склейках не бывает физически, а поиск паузы нужен ровно для одного — не рвать слово посередине при нарезке кадров. Границы кадра выбираются как ближайший межсловный интервал и притягиваются к границе кадра при частоте нормализации (30 fps, `server/utils/render.ts`). Менять частоту на 24 незачем: важно единство, и оно уже обеспечено.

### 4.4 Чем единый трек хуже нарезки

Решение не бесплатное, и его цена должна быть записана рядом с выигрышем.

| Минус | Величина | Чем гасим |
|---|---|---|
| Нельзя переозвучить одну фразу | Правка слова меняет весь текст → новый трек → все аватарные кадры заново. TTS на ролик ~$0.07, lip-sync ~$0.7: правка стоит как новый ролик | Локальная замена сегмента (§4.5) |
| Синтез недетерминирован | У `minimax/speech-02-turbo` в payload нет `seed` (в отличие от картиночных и видеомоделей). Тот же текст даст другое звучание, подставить старые клипы к новому треку нельзя | Локальная замена сегмента; перегенерация целого трека остаётся осознанно дорогой операцией |
| Паузы задаёт модель, а не монтаж | Перебивке нельзя выделить две секунды тишины, если чтец их не сделал | Явные маркеры пауз в сценарии (§4.6) |
| Зависимость от транскрипции выше | Без word-timings границы кадров неизвестны вовсе, тогда как посценная схема знает их по построению | Деградация §10; транскрипция дешёвая и её отказ редок |

Переиспользование lip-sync сегодня привязано к тексту реплики (`hashSpeechIdentity` в `server/utils/presenter/scene-clip-mapping.ts`: текст + модель + голос + язык + темп), а не к байтам аудио. При едином треке ключом становится текст всего ролика — это и делает точечную правку дорогой без §4.5.

### 4.5 Локальная замена сегмента

Инструмент починки, а не основной путь. Оператор правит одну фразу — синтезируется **только она** и вклеивается в трек по границам пауз: ближайшее тихое место с обеих сторон, притяжка к границе кадра, кроссфейд в несколько миллисекунд.

Это ровно тот механизм, который в разобранной системе работает всегда; у нас он включается точечно. Пересобираются только кадры, чьи границы сдвинулись, — остальные и их lip-sync остаются оплаченными один раз.

Перегенерация трека целиком остаётся доступной, но помечается в UI как дорогая: она обесценивает все аватарные кадры ролика.

### 4.6 Маркеры пауз

В тексте сценария допускаются явные маркеры паузы заданной длины. При синтезе они превращаются в тишину нужной длительности (вставкой в трек, а не надеждой на чтеца). Так монтаж получает управляемый ритм: перебивка может занять свои две секунды, даже если модель прочитала текст без остановки.

## 5. План монтажа

### 5.1 Разделение ответственности

**LLM выбирает смысл**: что показать в этом отрезке, каким ведущим, из какого фона, какая идея у генерируемой картинки.
**Код считает секунды**: границы кадров, покрытие таймлайна, соответствие потолку длительности lip-sync модели.

Причина не теоретическая. Автор разобранной системы прямо описывает, как модели «серьёзно тупили при реализации плана монтажа» и нарушали инструкции на русском. Модель, которой поручена арифметика таймлайна, рано или поздно вернёт кадры с дырой или нахлёстом, и это увидит зритель.

### 5.2 Новые сущности

**`EditProfile`** — монтажный профиль:

| Поле | Смысл |
|---|---|
| `editPrompt` | Правила словами: чередование ведущих, что под кого подставлять, чем открывать ролик |
| `brollRatio` | Целевая доля перебивок (по умолчанию 0.4 — решение от 14.08) |
| `shotChangeSec` | Целевой шаг смены картинки (1.5–2 с) |
| `pipEnabled`, `pipPosition`, `pipSize` | Наложение ведущего поверх фона |
| `generativeVideoEnabled`, `generativeVideoBudgetUsd` | Разрешение и потолок дорогих фонов на ролик |
| `stepwiseApproval` | Пошаговый режим |
| `llmModelId` | Конкретная версия модели монтажа |

Профиль принадлежит бренду/шаблону производства. Ролик наследует; оператор перебивает полем на `Video`. Автономный режим берёт из профиля — человек в цикле не нужен.

Фиксация `llmModelId` — прямой вывод из разобранного опыта: полуавтоматические системы надо тестировать на конкретной версии модели, иначе смена версии меняет поведение молча.

**`BackgroundClip`** — библиотека фонов, устроенная как `PresenterSourceClip`: файл в хранилище, `sha1` для дедупа, длительность, вид (`screen_recording` / `footage` / `image`), теги, `usageCount` и `lastUsedAt` для cooldown, перцептивный хэш.

**`VideoShot`** — кадр смонтированного ролика: `videoId`, `order`, `startSec`, `endSec`, `sceneOrder`, передний план (`presenter` / `none`), задний план (`library` / `image` / `video` / `app_screen` / `none`) со ссылкой на источник, `idea`, флаг PiP, статус, путь к готовому ассету, стоимость, `perceptualHash` готового кадра.

Отдельная таблица, а не Json на ролике: она даёт перегенерацию одного кадра без пересборки соседей, идемпотентность шага и аудит стоимости по кадрам.

Хэш кадра здесь не для галочки: этап 7 спеки от 14.08 требует отпечатка по сетке 1–2 секунды вместо трёх точек, потому что платформы сравнивают именно последовательность хэшей. При шаге монтажа 1.5–2 с граница кадра почти совпадает с шагом сэмплирования, и отпечаток ролика собирается из уже посчитанных значений — отдельный проход по готовому файлу становится не нужен.

### 5.3 Валидация и ремонт

После ответа модели план проверяется чистой функцией: кадры покрывают таймлайн без дыр и нахлёстов; ни одна граница не рвёт слово; presenter-кадр не длиннее потолка lip-sync модели (иначе дробится, см. ниже); ссылки на фоны существуют; доля перебивок в допуске; генеративное видео не назначено кадру короче пяти секунд (§7).

Нарушения сначала чинятся детерминированно — притяжкой границ к ближайшему межсловному интервалу. Повторный запрос к модели идёт только если после ремонта план всё ещё невалиден, и в запрос кладётся текст ошибки.

**Дробление длинной реплики.** Реплика длиннее потолка lip-sync модели (у `kling-lip-sync` это 10 с) не помещается в один кадр. Дробить её по таймеру нельзя: склейка двух вырезок из разных мест записи посреди слова читается как рывок. Порядок такой:

1. резать по самой длинной паузе внутри реплики — там смена плана выглядит намеренной;
2. если подходящей паузы нет — ставить между частями перебивку, тогда склейка двух ракурсов ведущего вообще не встречается в кадре;
3. и только если запрещено и это — резать по ближайшему межсловному интервалу с записью WARN в лог шага.

## 6. Ведущий: записи, нарезка, lip-sync, PiP

### 6.1 Хранение исходных записей

Сегодня длинная запись не сохраняется: `server/api/characters/[id]/source-recordings/index.post.ts` пишет её во временную папку, режет на клипы 2–10 секунд и оставляет от исходника только имя в `sourceRecording` и смещение в `sourceStartSec`.

Это не только блокирует нарезку под длину речи. Сегодня падение ingest на середине означает повторную заливку до двух гигабайт, а перенарезка библиотеки по новым правилам невозможна в принципе — материала больше нет.

**Модель `PresenterRecording`:**

| Поле | Смысл |
|---|---|
| `characterId` | Чья запись |
| `storageKey`, `storageProvider` | Нормализованный файл в объектном хранилище |
| `sha1` | Дедуп по **оригиналу** до нормализации: повторная заливка того же файла не создаёт вторую запись |
| `durationSec`, `fps`, `width`, `height`, `bytes` | Параметры нормализованного файла |
| `originalName`, `originalBytes` | Что именно загрузили |
| `retention` | `keep` / `auto` — попадает ли запись под автоочистку |
| `ingestStatus`, `ingestError` | Состояние нарезки; позволяет перезапустить её без повторной заливки |

`PresenterSourceClip` получает необязательный `recordingId`. Существующие клипы остаются с `null`; поля `sourceRecording` и `sourceStartSec` сохраняются как исторические. Старые ролики продолжают собираться прежним путём — это условие §«До удаления старого пути сначала подтвердить работу его замены» из `AGENTS.md`.

**Что именно нормализуем.** H.264, 30 fps, AAC, ограничение по большей стороне 1920, **исходное соотношение сторон сохраняется**. Кропать в 9:16 при загрузке нельзя: тогда исчезнет свобода кадрирования, ради которой всё и затевается — крупный план, средний план, PiP-окно берутся из одного материала разными кропами, и каждый такой кроп меняет последовательность перцептивных хэшей, то есть работает на уникальность.

Оригинал 4K60 не храним: в ролик уходит 1080p, а разница в объёме кратная.

**Объём и жизненный цикл.** Минута нормализованной записи — примерно 30–37 МБ. При потоке около 300 единиц материала в месяц это от ~20 ГБ в месяц при коротких дублях до ~110 ГБ при десятиминутных. Поэтому:

- записи со статусом `auto`, у которых не осталось активных клипов, удаляются через настраиваемый срок;
- холодный класс хранения после 30 дней;
- в UI персонажа видно, сколько занимают его записи;
- ручная пометка `keep` защищает ценный материал от автоочистки.

**Повторная нарезка.** Отдельная операция: перенарезать запись по текущим правилам, не прося пользователя загружать её снова. Новые клипы проходят тот же контроль похожести по перцептивному хэшу, дубли не создаются.

### 6.2 Нарезка под речь

Два режима:

1. **есть запись-родитель** — фрагмент вырезается под фактическую длину кадра (`-ss` по записи, притяжка к границе кадра);
2. **записи нет** — прежний подбор ближайшего клипа по длительности.

`adjustAudioTempo` из аватарной ветки уходит: подгоняем картинку под голос, а не голос под картинку.

**Учёт использования переезжает с клипов на интервалы.** Сегодня `usageCount` и `lastUsedAt` живут на `PresenterSourceClip`, и cooldown работает потому, что клип — фиксированная единица. При нарезке по требованию единицей становится произвольное окно записи, у которого счётчика нет: без отдельного учёта требование §7 `PROJECT_CONTEXT` («cooldown повторного использования фрагмента») перестаёт выполняться ровно там, где включается главная фича.

Поэтому добавляется `PresenterRecordingUsage`: `recordingId`, `startSec`, `endSec`, `videoId`, `usedAt`. Выбор окна идёт по записи с наименьшим перекрытием с уже использованными интервалами и с учётом давности: окно, занятое вчера, не берётся сегодня, пока в записи есть нетронутые участки. Перцептивный хэш первого кадра выбранного окна проверяется против недавно использованных — так же, как сейчас при ingest.

Резервирование окна атомарно, как и резервирование клипа сейчас: параллельные прогоны не должны получать один и тот же участок.

### 6.3 PiP строго после lip-sync

Порядок жёсткий: вырезали фрагмент → отдали в lip-sync целым кадром → и только потом кроп, маска, скругление, наложение. Модель не находит лицо в заранее вырезанном кружке и синхронизирует плохо — на этом автор разобранной системы потерял время и перестраивал алгоритм.

У нас правило закрепляется структурно: функция композиции принимает уже синхронизированный клип и не может быть вызвана раньше.

### 6.4 Звук клипов

Дорожки клипов ведущего идут в сборку с нулевой громкостью. Сегодня они микшируются на 0.3 (`clipVolumeWithVoiceover` в `server/utils/video-pipeline.ts`), и это работает лишь потому, что voiceover собран из тех же файлов и совпадает по фазе. При едином треке совпадения не будет — получилась бы двойная речь с эхом.

Аватарный маршрут `speech_to_video` возвращает видео со звуком; риск двойного микса отмечен в спеке от 14.08 и закрывается тем же правилом.

## 7. Фоны и стоимость

Источники фона кадра, в порядке дешевизны:

| Источник | Цена | Когда |
|---|---|---|
| `BackgroundClip` из библиотеки | 0 | Запись экрана, лид-магнит, канал, готовая съёмка |
| Скрин приложения (`AppReferenceImage`) | 0 | Уже поддержано |
| Картинка `flux-dev` + движение монтажом | $0.025 за кадр | Основной путь перебивки |
| Сгенерированное видео | от $0.225 за клип | Только кадры длиной от 5 с, по флагу профиля и в пределах потолка |
| Пустой фон | 0 | Кадр отдан ведущему на весь экран |

Поверх любого может лечь Remotion-инфографика — план оверлеев уже написан (`server/utils/remotion/overlay-plan.ts`).

Промпты для генерации собираются из поля `idea` кадра; для этого переиспользуются существующие агенты визуального стиля и валидатор промптов сцены.

**Генеративное видео короче пяти секунд не существует.** Длительность квантуется в 5 или 10 секунд (`REPLICATE_KLING_16_DURATIONS` в `server/utils/media-provider/model-specs.ts`), поэтому двухсекундная перебивка обошлась бы в цену пятисекундного клипа — $0.225 при $0.045/с, в девять раз дороже картинки с движением, причём три секунды оплаченного материала уходят в мусор.

Правило: генеративное видео допустимо **только для кадров длиной от 5 секунд** — открывающий хук, финальный кадр, длинная перебивка под тезис. Планировщик не имеет права поставить его на короткий кадр; такая заявка отклоняется валидацией плана до оплаты, а не после. Кадры короче идут картинкой с движением всегда.

**Потолок стоимости обязателен.** При его исчерпании кадр не ломается, а деградирует до картинки с движением, и это пишется в лог шага. На 300 роликов в сутки разница между $0.025 и $0.225 за перебивку — это разница между рабочим сервисом и несогласованным счётом.

**Транскрипция — регулярная статья расхода.** Она выполняется на каждый ролик, то есть при целевой мощности 300 роликов в сутки оплачивается 300 раз в день. Её тариф обязан попасть в смету ролика (`estimate-cost`) и в суточный расчёт при снятии цены со страницы модели (§14) — способность без подтверждённого тарифа остаётся `integrated: false`, как и аватарные модели без цены.

## 8. Сборка, звук, субтитры

Видеослой — конкатенация кадров, приведённых существующей нормализацией к единому кодеку, размеру и частоте. PiP накладывается overlay-фильтром с позицией и размером из профиля.

Аудио: непрерывный voiceover как главный lane, музыка с ducking, дорожки клипов в ноль.

Если lip-sync вернул клип иной длины, чем заказано, правится **видео** — подрезкой или удержанием последнего кадра. Звук не трогается никогда: он эталон таймлайна.

Субтитры: текст из сценария, тайминги из выравнивания. В рендере ASS не меняется ничего — меняется только источник word-timings, и караоке-пресеты начинают попадать в слог.

## 9. Интерфейс

| Экран | Что добавляется |
|---|---|
| Персонаж | Загрузка образца голоса, вызов `minimax/voice-cloning`, сохранение пары `voiceId` + `voiceModelId`, видимый статус. Логика есть в `scripts/clone-voice.ts` — выносится на сервер вместе с её проверками: MP3/M4A/WAV, от 10 секунд до 5 минут, меньше 20 МБ. Прогон стоит **$3**, поэтому кнопка требует явного подтверждения суммы — как `--yes` в скрипте |
| Библиотека фонов | Загрузка и список по образцу исходников ведущего |
| Монтажный профиль | Форма правил; поле переопределения на ролике |
| План монтажа | Таблица кадров с превью, перегенерация отдельного кадра |
| Озвучка | Правка отдельной фразы с локальной заменой сегмента; перегенерация всего трека доступна, но помечена как дорогая — она обесценивает все аватарные кадры |
| Записи ведущего | Список записей, занимаемый объём, пометка `keep`, повторная нарезка, перезапуск упавшего ingest |
| Ролик | Пошаговый режим: ожидание решения после каждого шага, кнопки «принять» и «перегенерировать» |

**Пошаговый режим ждёт вне прогона.** Шаг доводится до конца, ролик переходит в статус ожидания решения, блокировка ролика отпускается, процесс завершает работу. Кнопка «принять» запускает **новый** прогон, который поднимает состояние из снапшотов и идёт дальше.

Ждать оператора внутри живого прогона нельзя: удержанный lock и подвешенный процесс не переживают перезапуск воркера, а требование «долгие операции идемпотентны и восстанавливаемы после рестарта» из `AGENTS.md` относится и к ожиданию. Watchdog ролики в этом статусе зависшими не считает. Автопродолжения по таймауту нет — оно обесценило бы сам режим.

Страницы проходят через `$design-feature` по правилам `AGENTS.md`: сначала макет в `design-preview`, потом интеграция отдельной задачей.

## 12. Тесты

**Без БД:** выравнивание транскрипции; валидация и ремонт плана; расчёт границ кадров; дробление длинной реплики по паузе; планирование нарезки под длину речи; аргументы PiP-композиции и нулевая громкость дорожек клипов; маппер спеки транскрипции; отказ плана при генеративном видео на коротком кадре; деградация при исчерпании потолка; выбор источника фона; точка вклейки при локальной замене сегмента.

**С БД:** идемпотентность новых шагов (повтор не оплачивает); перегенерация одного кадра не трогает соседей; после локальной замены сегмента пересобираются только сдвинувшиеся кадры и в таймлайне нет дыр; cooldown интервалов записи и фонов; наследование монтажного профиля роликом; ролик в ожидании решения не держит блокировку и переживает рестарт процесса.

**Canary (реальные деньги, бюджет до $20 по решению от 14.08):** один цельный ролик новым маршрутом плюс тот же сценарий старым — сравнение звука на стыках, попадания субтитров и стоимости.

## 13. Риски

| Риск | Как гасим |
|---|---|
| Модель транскрипции не отдаёт word-level тайминги для русского | Проверяется до включения; при отказе остаётся нынешняя оценка, ролик собирается |
| Правка одной фразы обесценивает все аватарные кадры | Локальная замена сегмента (§4.5); полная перегенерация трека помечена в UI как дорогая |
| Синтез недетерминирован (`seed` у TTS-спеки нет) | Тот же текст не воспроизводится байт в байт, поэтому подстановка старых клипов к новому треку запрещена на уровне ключа идемпотентности, а не оставлена на удачу |
| Хранение записей растёт до ~110 ГБ в месяц при длинных дублях | Нормализация вместо оригинала, автоочистка `auto`-записей без активных клипов, холодный класс после 30 дней, видимый в UI объём |
| Генеративное видео на фон съедает бюджет | Флаг профиля выключен по умолчанию, потолок на ролик, минимальная длина кадра 5 с, деградация до картинки |
| Cooldown ломается при переходе на нарезку по требованию | Учёт использованных интервалов записи вводится тем же этапом (4b), а не «потом» |
| Ожидание оператора подвешивает процесс | Ожидание вне прогона: статус, отпущенная блокировка, продолжение новым прогоном |
| Двойная речь в сборке | Дорожки клипов в ноль; проверяется реальным прогоном, а не только тестом |
| Переделка ломает работающий контур | `EDIT_PIPELINE` держит оба маршрута до canary-сравнения |

## 14. Предпосылки к реализации

1. **Токен Replicate.** В локальном окружении его нет (`.env` содержит только `REPLICATE_MOCK_MODE`). Без него нельзя снять схему модели транскрипции и подтвердить тариф — шаг 1 плана до этого не закрывается.
2. **Тариф модели транскрипции** берётся со страницы модели: API Replicate цены не отдаёт.
3. **Разворот решения от 14.08** про генеративное видео на перебивку зафиксирован здесь как опция с потолком; `docs/PROJECT_CONTEXT.md` §15–16 обновляется после приёмки этой спеки.
4. **Дизайн-флоу.** Новые экраны идут через `$design-feature` и попадают в продукт отдельной задачей.
