## 1. Резюме

Сайт функционально работает: все 30+ страниц открываются, навигация консистентна, шапка единая. Однако в коде накопился долг по UI-консистентности — особенно вокруг DaisyUI 5 миграции и эталонной модалки. Часть модалок не зеркалит `AccountCreateModal`: разные размеры шрифтов кнопок, утаревшие классы `*-bordered`, не везде есть `text-xs` подзаголовок.

**Критическое:**
- **68 случаев устаревших классов `input-bordered` / `textarea-bordered` / `select-bordered`** в 18 файлах — DaisyUI v5 эти модификаторы не использует, border включён по умолчанию.
- В 6+ модалках кнопки `btn` без `btn-sm`, инпуты без `input-sm` — визуально на 30% крупнее эталонных.

**Регрессий, ломающих UX, не обнаружено.** Все находки — косметические, но влияют на восприятие плотности интерфейса.

## 2. Эталон — AccountCreateModal

`app/components/account/AccountCreateModal.vue` (строки 149-343). Применять везде:

```vue
<dialog ref="dialogRef" class="modal">
  <div class="modal-box max-w-2xl">                    <!-- max-w-2xl для форм / max-w-lg для коротких -->
    <h3 class="font-bold text-lg mb-1">Заголовок</h3>
    <p class="text-xs text-base-content/60 mb-4">Подзаголовок-объяснение</p>

    <div class="space-y-3">
      <fieldset class="fieldset">
        <legend class="fieldset-legend">Поле *</legend>
        <input class="input input-sm w-full" />          <!-- ВСЕГДА input-sm, никаких input-bordered -->
      </fieldset>
    </div>

    <div class="modal-action">
      <button class="btn btn-sm btn-ghost">Отмена</button>          <!-- ВСЕГДА btn-sm -->
      <button class="btn btn-sm btn-primary">Создать</button>
    </div>
  </div>
  <form method="dialog" class="modal-backdrop">
    <button>close</button>
  </form>
</dialog>
```

**Закрытие:** через `defineExpose({ open, close })` + `dialogRef.value?.showModal()/close()`.
**Размер по типу:** `max-w-lg` — confirm, `max-w-xl` — мини-форма, `max-w-2xl` — стандарт, `max-w-3xl` — широкая со списком, +`max-h-[85vh] overflow-y-auto` если длинная.

## 4. UX/UI фичи, которые стоит имплементировать

### F1. Централизованная toast/notification система

Текущее состояние: ошибки показываются в `alert` внутри модалок, а действия типа «удалено» — без обратной связи (в `Onappear/onsave` ничего). Нужен:
- `useToast()` composable с `toast.success() / .error() / .info()`
- DaisyUI компонент `<div class="toast toast-end">` (есть в v5)
- Авто-dismiss через 3-5 с

Покрытие: ~30 мест в `useXxxActions.ts` где ловятся ошибки.

### F2. Loading skeletons вместо spinner

Текущее: `<span class="loading loading-spinner loading-lg">` посреди пустоты. DaisyUI 5 имеет `<div class="skeleton h-32 w-full">` — лучше для перцептивной скорости.

Применить на:
- `/accounts` (грид карточек)
- `/scenarios`, `/videos`, `/uploads`, `/ideas`, `/trends`, `/creatives` (списки)
- `/admin/accounts-health` (таблица + summary)

### F3. Pagination на больших списках

`server/api/creatives.get.ts` уже делает «3 запроса + in-memory sort/page» — известное ограничение. Доп. issues:
- `/admin/users`, `/admin/apps` — без pagination
- `/scenarios`, `/videos`, `/uploads` — pagination есть но не везде с UI индикацией размера страницы

### F4. Mobile-нав drawer

На 375px шапка перестает быть удобной — `Производство / Медиа / Аналитика` это dropdown-кнопки + 4 ссылки + Theme + Logout = много. DaisyUI имеет `<div class="drawer">` — burger-меню для mobile.

### F5. Keyboard shortcuts hint

`PipelineCreateModal` уже имеет «Ctrl+S hint» в toolbar. Распространить на другие модалки:
- Enter — submit primary
- Esc — close (уже работает через `<dialog>`, но не везде декларировано)
- `?` — открыть глобальный shortcuts hint modal

### F6. Empty states унификация

`SharedEmptyState` уже есть и используется в `/accounts`, `/scenarios` и др. Но в:
- `admin/telegram/Chats.vue` (свой inline)
- `admin/users/index.vue`
- `references/index.vue`

— используется ad-hoc копия. Привести к `SharedEmptyState`.

### F7. Sticky modal footer для длинных форм

В `AccountEditModal`, `TaxonomyManager`, `PostingJobCreateModal` есть `max-h-[85vh] overflow-y-auto` на modal-box, но `modal-action` скроллится с контентом → кнопки уезжают вниз и приходится скроллить. Решение: `flex flex-col` на `modal-box` + `flex-1 overflow-y-auto` на body + sticky footer.

### F8. Tooltip-helpers на сложных полях

`PostingJobCreateModal` использует `title=` на datetime-кнопке — это нативный тултип. DaisyUI имеет `class="tooltip tooltip-top" data-tip="..."` — лучше для UX. Распространить на:
- AI-кнопки (`AiSuggestButton`) — пояснить «AI заполнит на основе…»
- Сложные select типа `postingMethod`, `proxyStatus`

### F9. Single-tab Drawer для AccountEditModal

`AccountEditModal` имеет 4 таба: Основное / Доступы / Прокси / Indigo / Прогрев / Метрики / Готовность. На mobile (375) tabs-bordered становятся wrap-grid. Лучше — `tabs tabs-lift` или `drawer` для табов.

### F10. PageGuide collapsed-by-default на mobile

`SharedPageGuide` на каждой странице — на 375 px съедает первый экран. Сделать collapsed по умолчанию (есть кнопка-toggle), сохранять состояние в localStorage по `guide-key`.
