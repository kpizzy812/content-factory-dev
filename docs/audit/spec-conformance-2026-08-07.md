## Риски и открытые вопросы к заказчику

**Риски.**

1. **Флагманский пресет сейчас не запускается вообще.** `requireApprovedLeadMagnet: true` + отсутствие способа утвердить лид-магнит = партия падает на quality gate. Демонстрировать «фабрику» до P0-3/P0-4 нечем.
2. **Деньги на выключенном тормозе.** `/stop` не останавливает цикл, дублирование трендов ничем не ограничено на уровне БД, лимиты просмотров отсекают ролики после оплаты Apify, лид-магнит генерируется на каждый прогон. При выходе на 300/сут это прямые расходы.
3. **Аналитика показывает числа, которых не измеряли.** YouTube shares = 0 как «замер», прирост подписчиков всегда пуст, порог отбора в референсы мёртв из-за шкалы. Заказчик увидит дашборд, поверит числам и примет по ним решения.
4. **Медицинская тематика без policy-чека.** Единственный барьер — просьба в промпте. Один ролик с обещанием гарантированного результата — это регуляторный и репутационный риск, а не «недоделанный чек».
5. **Уникальность не контролируется на выходе.** pHash только на входе библиотеки ведущего, cooldown фрагментов отсутствует, признаки не учитываются. При маленькой библиотеке серия роликов будет визуально однотипной — это ровно тот сценарий блокировок, о котором §7.
6. **Незакоммиченное дерево.** Вся волна правок по Replicate/lip-sync/публикации/метрикам (+5678 строк, 40 новых тестов) существует только в рабочей копии. Любой сбой машины или неаккуратный `checkout` — и половина закрытого списка вернётся в открытый.
7. **fal обязателен, Replicate опционален** — обратно тому, что согласовано. Отключение fal сегодня останавливает Модуль 3 целиком; миграция на Replicate меняет модель выполнения оркестратора (синхронный поллинг → webhook), то есть это не «замена вызова», а переработка видео-конвейера.
8. **300/сут ничем не подтверждены.** 5 параллельных прогонов и внутрипроцессный счётчик; бюджет одного ролика 24 минуты end-to-end при 300 задачах. Пока не сделан P0-19, целевая мощность — предположение.

**Вопросы, на которые нужен письменный ответ заказчика.**

1. **YouTube в Trendwatcher** — оставляем в объёме или сокращаем ТЗ до TikTok+Instagram? Сейчас реально работают две площадки.
2. **Досматриваемость и репосты для TikTok.** Официальный Display API в текущем наборе scope времени просмотра не отдаёт, репосты по YouTube Data API не отдаются вовсе. Принимаем «не измерено» письменно или расширяем scope/подключаем платные источники?
3. **Прирост подписчиков.** Apify-скрапер публичного профиля противоречит §4 («только белые инструменты»). Переходим на официальные API (меньше метрик, но чисто) или скрапер согласуется как допустимый источник?
4. **Три варианта сценария.** В автономном контуре сейчас один. Автогенерация трёх без человека, который выбирает, — это тройная стоимость LLM без пользы. Оставляем один вариант в автономном режиме и три в ручном, или вводим паузу «ожидает выбора оператора» в конвейере?
5. **CTR по ссылке.** Считается по нашей атрибуции и существует только для роликов, выпущенных через фабрику с трекинг-токеном. Ролики, залитые вручную, CTR не получат никогда. Принимается?
6. **Интеграция с MarketingCamp.** По SPEC обязательна, по PROJECT_CONTEXT §11 — снята и выключена (404 на `/api/ideas/sync`). Нужно решение: восстанавливаем, оставляем выключенной или закрываем формально изменением ТЗ.

8. **Remotion.** Инфографику первой версии можно деградировать до статических кадров + субтитров — ролик соберётся. Нужно ли поднимать полноценный Remotion-рендер (Chromium в контейнере, влияние на деплой) в текущем объёме?
