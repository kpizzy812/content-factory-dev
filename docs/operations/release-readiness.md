# Готовность к показу и к первой партии

Проверочный список перед тем, как показывать фабрику заказчику или запускать партию на реальных деньгах. Составлен 07.08.2026 по итогам аудита соответствия ТЗ.

Порядок важен: каждый следующий блок бессмыслен, пока не закрыт предыдущий.

## 1. Контент, который увидит заказчик

- [ ] **Библиотека ведущего заполнена материалами заказчика.** Сейчас в ней лежит стороннее видео с Викисклада, а персонаж называется «Тестовая ведущая» — это техническая проверка цепочки, а не демо. Готовый ролик, собранный на этом материале, показывать нельзя.
- [ ] Лид-магнит утверждён (`PATCH /api/factory/lead-magnets/:id`, статус `approved`) — иначе флагманский пресет не стартует: quality gate требует утверждённый материал.
- [ ] Воронка активна и у неё задано кодовое слово — CTA сценария строится вокруг него.

## 2. Переменные окружения

Публикация и платные вызовы выключены по умолчанию — это правильно для разработки и неверно для показа.

- [ ] `ENABLE_PAID_APIS=true` — без него нет генерации, музыки и анализа.
- [ ] `ENABLE_SOCIAL_POSTING=true` — иначе загрузки создаются в статусе `blocked_by_env`. Планировщик подхватит их сам после включения (это починено), но до включения ничего не публикуется.
- [ ] `ENABLE_AUTOMATION_SYNC=true` — без него не работает цепочка «комментарий с кодовым словом → ChatPlace → выдача лид-магнита», то есть воронка обрывается ровно там, где происходит конверсия. По умолчанию `false`.
- [ ] `SCHEDULERS_ENABLED` не равно `"false"` — планировщики выключены только явным `false`. Проверьте отдельно, что переменная не выставлена в `false` копипастой из `.env.test`.
- [ ] `REPLICATE_API_TOKEN`, `REPLICATE_WEBHOOK_BASE_URL` (публичный HTTPS), `REPLICATE_WEBHOOK_SIGNING_SECRET` — без базового URL и секрета конфигурация Replicate невалидна, и восстановление потерянных задач не запускается.
- [ ] `FAL_KEY` — пока изображения, клипы и речь идут через fal, без него Модуль 3 не работает вовсе.
- [ ] `MEDIA_PROVIDER_FALLBACK` — оставить пустым, если резерв на fal для lip-sync не нужен.

## 3. Деньги и лимиты

- [ ] Баланс Replicate пополнен. При остатке меньше пяти долларов действует лимит «один запрос за раз», и прогон девяти сцен растягивается примерно на сорок минут — это в одиночку определяет 67 минут на ролик в расчёте мощности.
- [ ] Баланс fal.ai пополнен.
- [ ] Квоты аккаунтов заполнены (`publishingQuotaTotal`/`publishingQuotaUsage`) — планировщик партии раскладывает нагрузку по ним, а при неизвестной квоте откатывается на фолбэк и пишет об этом в лог.
- [ ] Аккаунтов достаточно с запасом. Шесть аккаунтов по 50 публикаций дают ровно 300 в сутки — впритык. Расчёт: `bun run scripts/estimate-capacity.ts <параллельныеПрогоны> <аккаунтов>`.

## 4. Мощность

- [ ] Проверьте расчёт под свои числа: при пяти параллельных прогонах выходит 89 роликов в сутки, для 300 нужно 17.
- [ ] Настоящая партия 10–20 роликов пройдена до разговоров о 300 в сутки (требование `PROJECT_CONTEXT` п.12).

## 5. Чего не будет в первой версии

Скажите это заказчику до показа, а не после.

- Досматриваемость TikTok и репосты YouTube официальные API не отдают — в отчётах это «не измерено», а не ноль.
- Анимационной инфографики (Remotion) нет: ролик собирается статичными кадрами и субтитрами.
- B-roll как отдельного типа сцены нет — каждая секунда ролика стоит как AI-клип.
- Страницы «Фабрика» нет: воронки, лид-магниты и запуск партии доступны только через API.
- Trendsee не подключён, YouTube в поиске трендов не работает.
