# Replicate в ContentFactory

Replicate — основной провайдер медиа-моделей. Через него идут все шесть способностей: изображения (`black-forest-labs/flux-dev`), клипы text-to-video и image-to-video (`kwaivgi/kling-v1.6-standard`), синтез речи (`minimax/speech-02-turbo`), lip-sync (`kwaivgi/kling-lip-sync`) и аватарные сцены speech-to-video (`prunaai/p-video-avatar`). fal.ai не включается автоматически и используется только при `MEDIA_PROVIDER_FALLBACK=fal` после исчерпания повторов Replicate либо при явно выбранной fal-модели у ролика.

## Переменные окружения

```env
REPLICATE_API_TOKEN=
REPLICATE_WEBHOOK_SIGNING_SECRET=
REPLICATE_WEBHOOK_BASE_URL=https://factory.example.com
REPLICATE_DEFAULT_LIPSYNC_MODEL=kwaivgi/kling-lip-sync
REPLICATE_DEFAULT_TTS_MODEL=minimax/speech-02-turbo
REPLICATE_TTS_PRICE_USD_PER_1K_CHARS=0.06
REPLICATE_RECOVERY_ENABLED=true
MEDIA_PROVIDER_FALLBACK=
SCHEDULERS_ENABLED=true
ENABLE_PAID_APIS=true
```

`REPLICATE_WEBHOOK_BASE_URL` содержит только публичный origin без завершающего `/`. Итоговый адрес webhook:

```text
https://factory.example.com/api/webhooks/replicate
```

Signing secret получают тем же API token, под которым запускаются predictions:

```bash
curl -s -H "Authorization: Bearer $REPLICATE_API_TOKEN" \
  https://api.replicate.com/v1/webhooks/default/secret
```

Значение поля `key` из ответа записывается в `REPLICATE_WEBHOOK_SIGNING_SECRET`. Токен и signing secret нельзя коммитить или выводить в логи.

## Как проходит задача

1. ContentFactory считает SHA-256 исходного клипа и TTS-аудио.
2. Из video ID, scene order, хэшей файлов и модели строится стабильный idempotency key.
3. Локальные файлы загружаются через Replicate Files API.
4. Prediction создаётся асинхронно и сразу записывается в `MediaPrediction`.
5. Завершение приходит на подписанный webhook. Повторная доставка безопасна.
6. Если webhook потерялся, recovery-поллинг запрашивает prediction по ID.
7. Успешный output сразу копируется в настроенное постоянное хранилище.
8. Pipeline получает локальную копию сохранённого результата и продолжает FFmpeg-сборку.

URL файлов результата Replicate временные, поэтому состояние `succeeded` не считается готовым для pipeline, пока не заполнен `persistedStorageKey`.

## Ограничения текущей модели

- видео: `.mp4` или `.mov`, меньше 100 МБ;
- длительность одного исходного клипа: от 2 до 10 секунд;
- разрешение: 720p-1080p, допустимые размеры 720-1920 px;
- аудио: `.mp3`, `.wav`, `.m4a` или `.aac`, меньше 5 МБ;
- цена: `$0.014` за секунду выходного видео;
- входные данные обрабатываются Replicate и поставщиком модели Kuaishou, поэтому нельзя отправлять материалы без нужных прав и согласий.

Ограничение 2-10 секунд относится к сцене, а не ко всему ролику. Ролик длиной 70-90 секунд собирается из нескольких коротких сцен.

## Синтез речи

Русская озвучка идёт через `minimax/speech-02-turbo`. Раньше в реестре стояла `fal-ai/kokoro/russian`, но такого эндпоинта не существует: fal.ai отдаёт на него 404, а у самого Kokoro русского языка нет — только английский, японский, китайский, испанский, французский, хинди, итальянский и португальский. Запись Kokoro осталась в реестре с `integrated: false`, чтобы старые `Video` с этим `voiceoverModelId` падали внятно, а не уходили молча в английский голос.

Синтез проходит тем же путём, что и lip-sync: `MediaPrediction`, вебхук, recovery-поллинг, копирование в постоянное хранилище. Idempotency key считается по самому запросу — модель, текст, голос, скорость и язык. Одна и та же реплика тем же голосом второй раз денег не стоит, даже если её просит другая сцена или другой ролик.

Голос задаётся идентификатором MiniMax (`Wise_Woman` по умолчанию), а не ISO-кодом языка. Язык передаётся отдельным полем `language_boost`.

Цена берётся из `REPLICATE_TTS_PRICE_USD_PER_1K_CHARS`, потому что Replicate не отдаёт её через публичный API. Значение по умолчанию — `0.06` за 1000 символов; перед пакетным запуском его нужно сверить с личным кабинетом, иначе аудит стоимости будет врать.

## Сцены ведущей не покупаются дважды

Сцена, у которой в сценарии заполнен `spokenLine`, снимается живой ведущей: фрагмент из библиотеки исходников идёт прямо в lip-sync. Для таких сцен не запускается ни text-to-video, ни генерация превью-кадра — платить за клип, который тут же выбрасывается, незачем. Раньше пайплайн делал именно это.

Следствие: ролику не нужен `FAL_KEY` — ни целиком собранному из сцен ведущей, ни смешанному. Ключ fal требуется только там, где fal выбран явно: моделью ролика или переменной `MEDIA_PROVIDER_FALLBACK`.

## Опорный кадр: не только приложение

Способность `image_to_video` оживляет любой референс, а не только скриншот приложения. Источник задаётся полем сцены `referenceFrame`:

| Источник | Таблица | Зачем |
|---|---|---|
| `app_screen` | `AppReferenceImage` | кадр приложения в сцене |
| `character` | `CharacterReferenceImage` | портрет ведущего, из него собирается AI-аватар |
| `scene` | `SceneReferenceImage` | референс атмосферы или композиции |

Устаревшее поле `appScreenRef` читается как `referenceFrame` с источником `app_screen` — снапшоты уже запущенных роликов и промпт сценариста продолжают работать. При наличии обоих полей выигрывает `referenceFrame`.

Файл кадра берётся из постоянного хранилища по `storageKey`; для записей `AppReferenceImage`, созданных до переезда в хранилище, остаётся чтение из каталога загрузок. Референс, которого нечем доставить, не уводит сцену в платную задачу с пустым входом — она снимается text-to-video, и причина пишется в лог шага.

Анкер «не ломай интерфейс» в negative prompt применяется только к источнику `app_screen`: портрету ведущего он вредит.

## AI-аватар вместо снятой ведущей

Персонаж не обязан быть снятым человеком. Если библиотека исходников не дала фрагмента под сцену, а у персонажа есть портрет, сцена снимается аватаром — способностью `speech_to_video`: портрет плюс готовое TTS-аудио, на выходе сразу говорящее видео со звуком.

Порядок выбора исходника для сцены с `spokenLine`:

1. фрагмент реальной съёмки из библиотеки → `lip_sync`;
2. библиотека пуста, у персонажа есть портрет → `speech_to_video`;
3. нет ни того, ни другого → сгенерированный клип, как раньше.

Ключевое: для аватарной сцены lip-sync **не запускается вовсе**. Речь уже в кадре и в звуковой дорожке, второй платный шаг там не нужен. Прежняя схема — оживить портрет через `image_to_video`, потом натянуть губы — стоила два вызова ($0.059/с против $0.025/с) и генерировала движение до того, как известно, что человек говорит. Разбор в `docs/superpowers/specs/2026-08-14-avatar-pipeline.md`.

Правила ветки:

- портрет выбирается по `kind="face"`; кадр в полный рост берётся, только если лица нет вовсе;
- длину сцены задаёт синтезированная речь, а не план: неизмеримое аудио — сцену аватаром не снимаем;
- потолок длины проверяет спека модели ДО оплаты (`fabric-1.0` — 60 секунд);
- стоимость попадает в ledger шага lip-sync по фактическому провайдеру;
- отказ модели не роняет шаг: сцена помечается пропущенной, следующий прогон попробует снова.

Модели способности и их состояние:

| Модель | Состояние | Почему |
|---|---|---|
| `prunaai/p-video-avatar` | включена | единственная с опубликованной ценой: $0.025/с в 720p, $0.045/с в 1080p |
| `veed/fabric-1.0` | выключена | 60 секунд одним куском, но цена не опубликована |
| `bytedance/omni-human` | выключена | принимает поясной и ростовой кадр, цена не опубликована |
| `wan-video/wan-2.2-s2v` | выключена | тариф по времени GPU, цена известна только после прогона |

Резерва на fal у этой способности нет: подходящих моделей там не подключено. Отказ Replicate означает отказ сцены — и это видно в логе шага, а не маскируется чужим провайдером.

Проверять аватар нужно canary на реальных деньгах: мок не покажет, как модель произносит русский и держит лицо между сценами.

### Уникальность аватарных сцен

`docs/PROJECT_CONTEXT.md` §7 прямо описывает риск, который создаёт аватар: одинаковый человек и фон дублем ролик не делают, но повтор пикселей и движений при меняющихся губах и субтитрах — делает. Один портрет, оживлённый одинаково во всех сценах, — это ровно тот случай. Поэтому в ветке три механизма.

**Ротация портретов.** Выбор идёт по «наименее использованный первым»: `CharacterReferenceImage.usageCount` и `lastUsedAt` — те же поля и тот же порядок, что у фрагментов ведущего в `PresenterSourceClip`. Счётчик растёт только за реально снятый клип: повторный прогон ролика переиспользует готовый prediction и ротацию не накручивает.

Внутри одного ролика счётчик помочь не может — он обновляется после сцены, а сцены идут подряд. Поэтому шаг ведёт список уже занятых портретов и передаёт его следующей сцене. Портретов меньше, чем сцен — список кончается, и кадр берётся повторно: сцена без картинки хуже, чем повтор.

**Разные движения даёт сама речь.** В `speech_to_video` мимика и пластика выводятся из аудио: разные реплики — разные движения, без заготовок. Промпт описывает внешность персонажа и настроение сцены, а не то, каким движением отличить клип от соседнего. Перебор микро-движений, который был нужен при оживлении портрета через `image_to_video`, отсюда убран.

**Контроль дублей внутри ролика.** С первого кадра снятого аватарного клипа снимается dHash (тот же алгоритм, что у библиотеки ведущего) и сравнивается с кадрами предыдущих аватарных сцен ролика. Совпадение пишет WARN в лог шага с номером сцены-близнеца и расстоянием в битах. Это предупреждение, а не блокировка: оплаченный клип выбрасывать нельзя, а решение о публикации принимает гейт уникальности (`server/utils/quality/video-uniqueness.ts`), который сравнивает готовый ролик с прошлыми публикациями.

Практический вывод для наполнения библиотеки: одного портрета хватает, чтобы ролик собрался, но разнообразия он не даст — ракурс, свет и одежда во всех сценах будут одни. Два-три кадра с разных углов заметно улучшают и идентичность, и вариативность. Генерация недостающих портретов из одного референса (character consistency) — этап 5 спецификации `2026-08-14-avatar-pipeline`.

## Mock-режим

Для разработки и CI:

```env
REPLICATE_MOCK_MODE=true
SCHEDULERS_ENABLED=false
ENABLE_PAID_APIS=false
STORAGE_DRIVER=mock
```

Mock создаёт детерминированный prediction ID, проходит те же состояния и не вызывает сеть. Для быстрой проверки новых модулей используется `vitest.pure.config.ts`; интеграционный тест использует отдельную test-БД.

## Recovery и fallback

Recovery запускается только когда одновременно выставлены:

```env
SCHEDULERS_ENABLED=true
REPLICATE_RECOVERY_ENABLED=true
```

Он обрабатывает задачи ограниченными пачками, восстанавливает потерянные webhook и повторяет незавершённое копирование output. Несколько процессов не должны сохранять один результат дважды: перед копированием берётся атомарная lease в БД.

По умолчанию fallback выключен. Чтобы разрешить fal.ai:

```env
MEDIA_PROVIDER_FALLBACK=fal
FAL_KEY=...
```

Fallback срабатывает только для retryable-ошибки Replicate после двух попыток. Ошибки конфигурации, валидации, БД и хранилища не маскируются переключением провайдера.

## Canary перед пакетным запуском

1. Применить Prisma-миграции и проверить подключение к постоянному хранилищу.
2. Настроить token, signing secret и публичный webhook URL.
3. Оставить `MEDIA_PROVIDER_FALLBACK` пустым, чтобы увидеть настоящую ошибку Replicate.
4. Взять один клип длиной 2-10 секунд и одно короткое TTS-аудио допустимого формата.
5. Запустить одну сцену, не пакет и не очередь на сотни роликов.
6. Проверить в `MediaPrediction`: один `externalId`, `status=succeeded`, `persistenceStatus=persisted`, заполненный `persistedStorageKey` и отсутствие секрета в snapshot.
7. Проверить итоговый клип глазами и на слух: синхронность губ, лицо, артефакты, звук и длительность.
8. Повторить тот же запрос и убедиться, что новый платный prediction не появился.
9. Только после успешного canary включать небольшую партию и затем увеличивать параллелизм.

Официальная документация: [async predictions](https://replicate.com/docs/topics/predictions/create-a-prediction), [проверка webhook](https://replicate.com/docs/topics/webhooks/verify-webhook/), [входные файлы](https://replicate.com/docs/topics/predictions/input-files), [временные output-файлы](https://replicate.com/docs/topics/predictions/output-files), [схема Kling Lip Sync](https://replicate.com/kwaivgi/kling-lip-sync/api/schema).

## Уникальность: что делает контур целиком

Три механизма работают на разных уровнях, и ни один не заменяет другие.

**Смена плана внутри сцены** (`server/utils/video-tools/shot-variation.ts`). Сцена перестала идти одним статичным кадром: при нормализации клипов к формату добавляется кадрирование с запасом 12% и медленное движение окна за время сцены — панорама влево, вправо, вверх, наезд или статичный тайт-план. План выбирается по индексу сцены детерминированно: пересборка ролика обязана давать тот же файл. Платных вызовов не добавляется вовсе, это чистый ffmpeg. Выключается `SHOT_VARIATION_ENABLED=false`.

**Отпечаток по сетке кадров** (`server/utils/quality/video-fingerprint.ts`). Раньше сравнивались три опорные точки — начало, середина, конец. Площадки работают иначе: сэмплируют кадры с шагом порядка 1–2 секунд и строят отпечаток как последовательность хешей. Теперь рядом с опорными кадрами считается сетка с шагом 2 секунды (один вызов ffmpeg на весь ролик, фильтр `fps`), а дублем считается совпадение двух третей последовательности при минимум пяти сравнимых кадрах. Записи истории без сетки продолжают сравниваться по трём кадрам — старые данные не обесцениваются.

**Ротация портретов и контроль дублей аватара** — описаны выше.

## Маркировка AI-контента

EU AI Act (Regulation 2024/1689) требует раскрытия AI-происхождения для аудитории в EU с 2 августа 2026, включая площадки за пределами EU, работающие на эту аудиторию.

Поля у платформ разные, и выдумывать их нельзя — лишний ключ отвергает запрос целиком:

| Площадка | Поле | Где |
|---|---|---|
| TikTok | `post_info.is_aigc` | Content Posting API, init направляемой публикации |
| YouTube | `status.containsSyntheticMedia` | Data API v3, `videos.insert`/`videos.update` |
| Instagram | нет | Meta размечает по метаданным файла, параметра запроса не существует |

Перевод в формат площадки — `server/utils/social/ai-disclosure.ts`. Флаг приходит в `UploadParams.isAiGenerated` и по умолчанию включён: ролики фабрики синтетические по построению — речь синтезирована, кадры сгенерированы, ведущий бывает аватаром. Явный `false` там, где поле есть, отправляется намеренно: это утверждение «контент не синтетический», а пропуск поля означал бы «мы не ответили».

## Перебивки (B-roll)

Решение от 14.08.2026: перебивка — это кадр плюс движение камеры, а не купленный клип.

Сцена без реплики (`spokenLine` пуст) получает изображение на шаге кадров и превращается в клип средствами ffmpeg: кадр вписывается в формат, поверх идёт панорама или наезд из общего набора планов (`video-tools/shot-variation.ts`), добавляется тишина в звуковой дорожке — без неё concat разводит субтитры с картинкой.

Деньги: девятисекундная перебивка стоила $0.41 через text-to-video ($0.045/с) и стоит $0.025 сейчас — цену одного кадра flux. Платного вызова на саму сцену нет вовсе.

Следствие для шага кадров: генерация изображений больше не пропускается, когда в ролике есть перебивки. Раньше кадры считались промежуточным артефактом и по умолчанию отключались; теперь они материал сцены. Смета это учитывает — из расчёта клипов уходят и сцены ведущей, и перебивки.

Целевая доля перебивок — около 40% хронометража (`broll-plan.ts`, `DEFAULT_BROLL_RATIO`). Отклонение больше чем на 15 процентных пунктов пишется предупреждением: ролик почти целиком из говорящей головы отличается от вчерашнего только губами, а ролик без ведущей вовсе — уже не тот продукт.

Выключается `BROLL_STILL_SCENES_ENABLED=false` — тогда сцены снова снимаются генеративным клипом.
