## Важно: приоритет изменился 14.08 вечером

Заказчик подтвердил, что **сырые видеоисходники Лианы есть**. Это переворачивает порядок: основной путь — липсинк по её реальным фрагментам, где подменяется только артикуляция, а мимика, взгляд и свет остаются настоящими. Аватар из фото остаётся запасным путём для сцен, под которые не нашлось фрагмента.

Заказчик отдельно высказал сомнение: «аватары все кривые выходят, а тут ещё и из фото». Возражение справедливое для оживления портрета и несправедливое для липсинка по видео — это разные механизмы. Ответ на него даёт не переписка, а canary: одна и та же реплика через липсинк по её фрагменту и через аватар из фото, рядом.

Поэтому порядок теперь такой: сначала прогон живого пути на её материале, потом canary со сравнением двух подходов, и только затем всё остальное.

**Параллельная сессия добавляет способность `image_to_image`** (`model-specs.ts:1398`, `registry.ts`, `tests/unit/fixes/image-to-image-registry.spec.ts`) — судя по всему, это и есть генерация вариаций портрета. Прежде чем браться за пункт 1, проверить, не сделано ли оно уже, и не дублировать.

## Что делать, по порядку

### 0. Прогон живого пути на материале Лианы (первое)

Загрузить сырые записи в библиотеку исходников (`POST /api/characters/:id/source-recordings` — сервер сам режет по границам сцен, до 2 ГБ за раз), проверить, сколько фрагментов приняла нарезка и сколько отбраковала как дубли по перцептивному хэшу. На однородной съёмке отбраковка большая — это измеренный факт, см. `presenter-library.md`.

Затем собрать ролик целиком: сцены ведущей через липсинк, перебивки из кадров, инфографика поверх. Это первый живой прогон всего, что сделано 14.08, — ожидать проблем на стыках.

### 1. Портреты из одного референса (может быть уже сделано параллельно)

Этап 5 спецификации `docs/superpowers/specs/2026-08-14-avatar-pipeline.md`. Сейчас аватару нужно 5–10 фотографий человека для ротации; с генерацией вариаций хватит одной-двух.

Суть: из загруженного портрета получить набор кадров того же человека в разных ракурсах, одежде и обстановке — character consistency. На Replicate это Flux Kontext или PuLID; **цену и схему входа снять с API до реализации**, как делали для speech_to_video:

```bash
curl -s "https://replicate.com/api/models/<owner>/<name>/versions" | node -e "..."
```

Цены через `/v1/models/...` не отдаются даже с токеном — только веб-страница модели под аккаунтом владельца.

Куда встраивать: рядом с `server/api/characters/[id]/generate-reference.post.ts`, который уже умеет генерировать референс персонажа. Нужна ветка «сделай N вариаций существующего кадра», а не «нарисуй с нуля по промпту». Результат ложится в `CharacterReferenceImage` теми же полями, что и загруженный, — ротация подхватит автоматически.

### 2. DB-сьюты (не гонялись)

Поднять `cf-tests-pg` (порт 5436, `tests/global-setup.ts` другой порт не примет) и прогнать целевой набор по изменённым модулям. Полная `tests/unit` идёт около 50 минут — её не запускать без нужды.

Особое внимание: миграция `CharacterReferenceImage`, ротация портретов, аватарная ветка не создаёт lip-sync задачу, перебивка не покупает клип.

### 3. Canary (ждёт пополнения Replicate)

Бюджет утверждён — до $20. Порядок из `docs/operations/replicate.md`:

1. одна русская реплика через `p-video-avatar` в 720p и в 1080p — **сравнить артикуляцию и решить разрешение**, разница в деньгах $2.0 против $3.6 за ролик;
2. по одному прогону на `text_to_image`, `text_to_video`, `image_to_video`, `text_to_speech`;
3. повтор каждого запроса — убедиться, что новый платный prediction не появился;
4. один цельный ролик со сценами ведущей и перебивками;
5. замерить, сколько занимает наложение инфографики Remotion (при первом рендере скачается headless Chrome, ~150 МБ).

### 4. Блочная съёмка (решение отложено до canary)

Если модель плохо держит лицо между отдельными сценами — переходить на блоки по 30–60 секунд, для этого включать `fabric-1.0` (60 секунд одним вызовом) после подтверждения его цены. Если держит — оставить посценную съёмку: она позволяет пересобрать одну сцену, не трогая соседние.

### 5. Пересчёт бэклога аудита

`docs/audit/spec-conformance-2026-08-07.md` — 19 задач p0, 30 p1, 14 p2 на 07.08. Медиаконтур, B-roll и часть уникальности с тех пор закрыты. Пройтись по списку и дать актуальную картину: что живо из p0.

## Принятые решения — не переспрашивать

Зафиксированы в `docs/superpowers/specs/2026-08-14-avatar-pipeline.md` §8:

- миграции схемы БД разрешены;
- B-roll — картинка плюс движение камеры, доля около 40%;
- Remotion внедряем, лицензия бесплатна (команда до трёх человек);
- бюджет canary до $20;
- ручная перегенерация сцены оператором не тратит бюджет попыток;
- A/B-варианты пока не делаем;
- число аккаунтов вне нашей зоны, «300 роликов в сутки» — требование к мощности производства.

## Правила работы

- **TDD обязателен**: тест пишется до кода и должен упасть по существу. Так сделана вся эта волна.
- **Проверка**: `bunx vitest run --config vitest.pure.config.ts` (чистая сьюта, ~10 секунд, 118 файлов / 1096 тестов на момент коммита) и `bunx tsc --noEmit -p .nuxt/tsconfig.server.json` — **базовый уровень 72 унаследованные ошибки**, рост означает поломку. Композиции Remotion проверяются отдельно: `bunx tsc --noEmit -p remotion/tsconfig.json`.
- **Схемы моделей и поля чужих API не выдумывать.** Снимать с API или документации и приводить дословно; неподтверждённая цена означает `billingConfirmed: false` и `integrated: false`.
- **Не запускать Workflow** — машина не тянет, процесс падает. Параллельные агенты пачками по два-три через Agent.
- В рабочем дереве могут появляться правки параллельной сессии — не откатывать чужое.
