# ContentFactory — принятые решения по дизайну

Проект идёт по брифу задачами 1→9, по одной за сообщение. Файлы: `00-system.dc.html` (система и оболочка), `01-dashboard.dc.html`, далее по номерам задач.

## Зафиксировано

**Палитра.** Одна фирменная тема, dark-first. Акцент — промышленный янтарь (палитра А). Токены и компоненты — в `00-system.dc.html`, секция 12 (`tokens.css`).

**Два акцентных токена.** `--color-accent` — яркий, только нетекстовое (полоса активного пункта, кольцо фокуса, прогресс, иконки, заливка кнопки), норма 3:1. Текст поверх заливки — почти чёрный `--color-on-accent`. Ссылки и текст акцентом — затемнённый `--color-accent-text`, 4.5:1 в обеих темах.

**Плотность.** 36 px — текстовая строка (по умолчанию, миниатюра 28×28). 44 px — строка с превью 32×32 или аватаром. На 1440×900 в списке 17–18 строк.

**Числа.** `font-variant-numeric: tabular-nums` во всех числовых колонках, метриках, времени и стоимости.

**Иконки.** Геометрические заглушки на сетке 24×24, stroke 1.5, скруглённые концы; каждый слот помечен комментарием `<!-- icon: mingcute:имя-line -->` для подстановки через `@nuxt/icon`.

**Поллинг (5 с, без SSE).** Индикатор обновления один, в топбаре, без спиннера и без мигания. Счётчики меняют только цифру, место под 3 знака зарезервировано. Строки таблицы не перерисовываются и не переупорядочиваются, пока пользователь сам не сменил сортировку; новые записи не вставляются в середину — плашка «＋N новых» сверху.

**Цвет нод конвейера.** Категория (Источники / Производство / Контроль / Выход / Служебные) — приглушённый низконасыщенный тон, только на левой полосе ноды 2–3 px и на иконке в палитре нод. Статус — полная насыщенность из пяти семантических, на рамке и бейдже, всегда перебивает категорию. Заметка — без категорийного тона.

Категорийный тон только там, где структура пространственная: канвас, палитра нод, компактная схема конвейера сбоку в мониторе запуска (пройденный путь подсвечивается поверх тона). В хронологии шагов монитора категории нет — тип ноды передаётся монохромной иконкой, цвет значит только статус. Диаграмма Ганта: полосы нейтральные, цветом отмечается только отклонение (упавший шаг, шаг, выбивающийся по длительности).

**Комментарии для переноса в Vue.** Повторяемые блоки размечены `<!-- component: ИмяКомпонента -->`; специфичное для конкретной сущности помечено как заменяемая часть.

**Повтор шагов генерации** (эндпоинты `rerun-step`, `skip-step`, `rerender-assembly`, `edit-subtitles`). Разделение по стоимости, а не по статусу: бесплатное и локальное — кнопкой прямо в строке шага (пересборка сцен, правка и перегенерация субтитров; у упавшего шага — «Повторить» и «Пропустить»); оплачиваемое — через меню шага с подтверждением и суммой (синтез речи, lip-sync, генерация видео, финальный рендер). Номер попытки показывается только при `attemptCount > 1`; расхождение `estimatedCost` и `actualCost` — только при расхождении.

**Раскладка графа — три разных случая.** «Выровнять по сетке» — кнопка на канвасе, безопасная, прилипание существующих позиций, ручная раскладка сохраняется. «Разложить по слоям» — в меню, разрушающая, слева направо по топологии; на графе крупнее 15 нод подтверждение «Ручная раскладка будет заменена»; проходит через общую историю, откатывается Ctrl+Z. Ноды без `position` раскладываются по слоям автоматически и молча при открытии, конвейер помечается `isDirty`. Если координаты есть у части нод (AI-автозаполнение дописало шаги) — раскладываются только ноды без координат, рядом со своими соседями по графу; существующие не двигаются.

**Лимиты платформ.** Instagram отдаёт только `quota_usage`/`quota_total` — время восстановления вычисляется по нашей истории публикаций и это прогноз (нижняя оценка: публикации мимо системы в неё не попадают). Агрегат от API — истина, прогноз — вспомогательный и подписан как прогноз («восстанавливается постепенно, полностью к…»). В таблице аккаунтов — «свободно сейчас + через час»; тип лимита читается явно: скользящее окно 24 ч (Instagram) против суточной квоты (TikTok/YouTube). Массовое планирование считает по кривой восстановления; перед каждой отправкой лимит перезапрашивается у API.

**Атрибуция — оба касания.** Цепочка касаний собирается группировкой AttributionEvent по `messengerUserId` и сортировкой по времени; это нижняя оценка (сшивается только опознанный пользователь) и подписывается так же, как прогноз лимитов. Последнее касание — для денег (KPI, сходится с CRM), первое — для контента (рейтинги хуков/трендов/источников, по умолчанию). В разборе публикации — строка «касаний: N · первое … · последнее …» с раскрытием цепочки. Окно атрибуции 30 дней — настройка (Задача 9), не зашито; что считать продажей (заявка/оплата/сделка) — подтвердить у заказчика.
